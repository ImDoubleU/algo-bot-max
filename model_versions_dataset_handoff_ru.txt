5. Что рандомизировалось при генерации седьмой версии датасета
===============================================================

Генератор создает синтетические FAR-сценарии на реальных параметрах domain-модели. Для каждого примера он:

1. Выбирает реальные размеры решетки.
2. Выбирает внутренний профиль сложности.
3. Создает случайную `ArrayConfiguration`.
4. Строит модельный конфиг через `CNNArrayComparator`.
5. Собирает входные тензоры через `cnn_phase_math.prepare_cnn_input(...)`.
6. Строит target semantics через `cnn_phase_math.build_target_semantics(...)`.
7. Отбрасывает невалидные варианты.
8. Центрирует реальную решетку в canvas `64 x 64`.

Рандомизируются:

- размеры решетки от `1` до `64` по каждой оси;
- частота;
- spacing `dx/dy` в длинах волн;
- beam steering;
- target azimuth/elevation;
- target distance;
- element type;
- polarization;
- разрядность фазовращателя `ps_bits`;
- amplitude law;
- Taylor и cosine параметры;
- phase errors;
- amplitude errors;
- random failure rate;
- manual disabled elements;
- manual excitation overrides;
- surface terrain/specular/diffuse/roughness;
- position errors;
- uniform/nonuniform geometry;
- runtime-флаг `infer_at_zero_steer`.

Фильтрация валидности:

- sample отбрасывается при ошибке сборки конфигурации;
- sample отбрасывается при `NaN` или `Inf`;
- sample отбрасывается, если доля активных элементов меньше `20%`.

В генераторе есть проверка:

```python
if active_ratio < 0.20:
    continue
```


6. Профиль phase_mix_v1
=======================

Финальный датасет использует профиль:

`phase_mix_v1`

Он является смесью:

- `25%` внутреннего easy-профиля `phase_easy_v1`;
- `35%` профиля `balanced_v2`;
- `40%` профиля `phase_hard_v1`.

Фактические counts в финальном датасете:

- `phase_easy_v1`: `29804`;
- `balanced_v2`: `42049`;
- `phase_hard_v1`: `48147`;
- всего: `120000`.

Easy-профиль дает более простые режимы:

- более центральные steering angles;
- более мягкие ошибки и failures;
- меньше nonuniform geometry;
- surface отключена;
- меньше manual overrides.

Hard-профиль повышает сложность:

- больше экстремальных spacing/frequency/failure regimes;
- выше вероятность position errors;
- выше вероятность surface;
- выше вероятность nonuniform geometry;
- выше вероятность manual dead patterns и manual excitations;
- более сильные phase/amplitude errors.


7. Углы и рабочий сектор
========================

Для рабочих steering/target сценариев enforce-ится front half-plane:

`[-50 deg, +50 deg]`

В metadata также видны domain границы:

- `angle_min_deg = -90`;
- `angle_max_deg = +90`;
- `front_half_plane_enforced_deg = [-50, +50]`.

Это не противоречие:

- `-90..+90` сохраняется как общий domain/diagnostic envelope;
- рабочие лучевые и целевые углы для генерации ограничиваются диапазоном `-50..+50`.

13. Какая версия сейчас лучше
=============================

По текущим артефактам лучше выбирать девятую версию модели как рабочую основную модель.

Причины:

1. Она уже экспортирована в `final_model.keras`.
2. Она уже прописана как default model path в UI.
3. Для нее есть test metrics и evaluation summary.
4. Ее постановка ближе к sequential синтезу amplitude/phase с учетом gain/objective.
5. На доступных polar evaluation cases она почти не смещает пик относительно reference и сохраняет focus ratio около `1.0`.

Седьмая версия модели при этом остается полезной:

1. Она имеет большой финальный датасет на `120000` samples.
2. Она использует компактный one-shot контракт.
3. Она потенциально должна быть быстрее девятой версии на inference, особенно для больших решеток.
4. Она может быть кандидатом на быстрый UI/runtime path, если серьезный run будет доведен до финального экспорта и покажет приемлемое качество.

16. Рекомендуемый честный benchmark
====================================

Если нужно решить, какая версия модели лучше не по статусу артефактов, а по одинаковым сценариям, надо прогнать обе версии на одном наборе FAR cases и сравнить:

- phase MAE;
- target peak error;
- predicted peak vs reference peak error;
- target dB gap;
- focus ratio;
- amplitude MAE;
- inference time;
- поведение на больших массивах;
- поведение при failures/manual inactive/manual overrides;
- поведение на surface/nonuniform geometry/position errors.

До такого benchmark-а вывод такой:

- по текущей готовности и подтвержденному качеству лучше девятая версия модели;
- по потенциальной скорости и компактному runtime path интереснее седьмая версия модели.
