# Ученики и статусы из amoCRM

Algo MAX может автоматически создавать ученика и менять его статус после перехода
сделки на нужный этап воронки amoCRM. Сопоставление выполняется по ID сделки.

## 1. Настройка сервера

Добавьте отдельный секрет в серверный `.env`:

```env
AMOCRM_WEBHOOK_SECRET=длинный-случайный-секрет
```

После изменения перезапустите API. Секрет нельзя добавлять в Excel или публиковать.

## 2. Ссылки для этапов воронки

Замените `n-novgorod` на идентификатор нужного филиала, а `SECRET` на секрет сервера.

Активный ученик:

```text
https://algo52.ru/api/v1/amocrm/student-status?tenant_slug=n-novgorod&student_status=active&secret=SECRET
```

Выбыл:

```text
https://algo52.ru/api/v1/amocrm/student-status?tenant_slug=n-novgorod&student_status=departed&secret=SECRET
```

Архив:

```text
https://algo52.ru/api/v1/amocrm/student-status?tenant_slug=n-novgorod&student_status=archived&secret=SECRET
```

## 3. Настройка в amoCRM

1. Откройте `Сделки` и нажмите `Настроить воронку`.
2. На этапе, где карточка нового ученика уже полностью заполнена, добавьте триггер
   `Отправить webhook` со ссылкой для статуса `active`.
3. На этапе, который означает выбытие ученика, добавьте такой же триггер со ссылкой
   для статуса `departed`.
4. На этапе восстановления используйте ссылку со статусом `active`.
5. При необходимости на архивном этапе используйте статус `archived`.

## 4. Поля для создания ученика

В карточке сделки должны быть заполнены пользовательские поля с точными названиями:

| Поле amoCRM | Обязательно | Назначение |
|---|---:|---|
| `ID ученика` | Да | Уникальный ID ученика из LMS или CRM |
| `Фамилия ребенка` | Да | Фамилия ученика |
| `Имя ребенка` | Да | Имя ученика |
| `Группа` | Да | Точное название группы |
| `Курс` | Да | Название курса |
| `Площадка` | Да | Площадка или филиал |
| `Преподаватель` | Да | ФИО преподавателя |
| `ID контакта` | Нет | ID родителя в amoCRM для последующей привязки |
| `Имя контакта` | Нет | ФИО родителя |

`ID сделки amoCRM` передается самим webhook, отдельное поле для него в карточке не нужно.

Если обязательные поля заполнены, Algo MAX создаст ученика, площадку при ее отсутствии,
нулевой счет астрокоинов и запись в истории. Повторный webhook с тем же ID сделки не
создает дубль. Если какого-либо поля нет, ученик не создается; ответ содержит
`incomplete_leads` с перечнем отсутствующих полей. После заполнения карточки webhook
можно отправить повторно.

amoCRM передает webhook как форму. Algo MAX берет `leads[status][0][id]`, находит
либо создает ученика по ID сделки и записывает событие в историю. Обрабатываются события
добавления, обновления и смены статуса сделки. Повторный webhook с тем же статусом ничего
не дублирует.

## 5. Проверка

1. Создайте тестовую сделку и заполните все обязательные поля из таблицы выше.
2. Переместите сделку на этап с webhook для статуса `active`.
3. Откройте `Управление` -> `Ученики` и найдите ученика.
4. Проверьте дату создания, активный статус и событие в истории ученика.
5. Повторно переместите или обновите сделку и убедитесь, что дубль не появился.

Ответ webhook содержит количество созданных, найденных и обновленных учеников. Если
`matched_students` равно `0`, а `incomplete_leads` заполнен, исправьте перечисленные
поля карточки. Если оба значения пустые, проверьте филиал в ссылке и формат события.
