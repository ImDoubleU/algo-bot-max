# Статус ученика из amoCRM

Algo MAX может менять статус ученика сразу после перехода сделки на нужный этап
воронки amoCRM. Сопоставление выполняется по ID сделки, который уже сохраняется
при импорте учеников.

## 1. Настройка сервера

Добавьте отдельный секрет в серверный `.env`:

```env
AMOCRM_WEBHOOK_SECRET=длинный-случайный-секрет
```

После изменения перезапустите API. Секрет нельзя добавлять в Excel или публиковать.

## 2. Ссылки для этапов воронки

Замените `n-novgorod` на идентификатор нужного филиала, а `SECRET` на секрет сервера.

Активный ученик:

```text
https://algo52.ru/api/v1/amocrm/student-status?tenant_slug=n-novgorod&student_status=active&secret=SECRET
```

Выбыл:

```text
https://algo52.ru/api/v1/amocrm/student-status?tenant_slug=n-novgorod&student_status=departed&secret=SECRET
```

Архив:

```text
https://algo52.ru/api/v1/amocrm/student-status?tenant_slug=n-novgorod&student_status=archived&secret=SECRET
```

## 3. Настройка в amoCRM

1. Откройте `Сделки` и нажмите `Настроить воронку`.
2. На этапе, который означает выбытие ученика, добавьте триггер `Отправить webhook`.
3. Вставьте ссылку со статусом `departed` и сохраните триггер.
4. На этапе восстановления добавьте ссылку со статусом `active`.
5. При необходимости на архивном этапе используйте статус `archived`.

amoCRM передает webhook как форму. Algo MAX берет `leads[status][0][id]`, находит
ученика по ID сделки и записывает смену статуса в историю ученика. Повторный webhook
с тем же статусом ничего не дублирует.

## 4. Проверка

1. Выберите одну тестовую сделку, ID которой уже импортирован в Algo MAX.
2. Переместите сделку на настроенный этап.
3. Откройте `Управление` -> `Ученики` и найдите ученика.
4. Проверьте новый статус и событие в истории ученика.

Ответ webhook содержит количество найденных и обновленных учеников. Если
`matched_students` равно `0`, в импорте нет ученика с переданным ID сделки либо
в ссылке выбран другой филиал.
