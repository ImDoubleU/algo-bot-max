# Черновик форматов данных и подключений

## Что уже можно проверить

Черновой сценарий бота:

1. Импортировать CRM XLSX в базу.
2. Запустить FastAPI backend.
3. Запустить MAX-бота.
4. В MAX отправить `/code <Contact ID>`.
5. Бот покажет связанных учеников.
6. Выбрать роль inline-кнопкой `Я родитель` или `Я ученик`.
7. Backend создаст связи доступа для этого MAX-аккаунта.
8. Открыть miniapp inline-кнопкой и проверить магазин, корзину, заказы, начисления и админскую загрузку товаров.

Это уже точка проверки человеком: нужно убедиться, что Contact ID находит правильных учеников, роль выбрана верно, miniapp открывается и данные соответствуют tenant.

## Формат CRM

Лучший формат для передачи CRM-данных мне и для импорта ботом: `.xlsx`, лист `Сделки`, одна строка = один ученик или одна сделка ученика.

Нужные колонки:

| Поле | Колонка в CRM | Обязательно |
| --- | --- | --- |
| ID сделки | `ID сделки` | желательно |
| UUID | `UUID` | желательно |
| LMS ID ученика | `ID ученика` | да, если есть |
| Имя ученика | `Имя ребенка из LMS` | да |
| Фамилия ученика | `Фамилия ребенка из LMS` | желательно |
| Группа | `Название группы LMS` | желательно |
| Курс | `Название курса из LMS` | желательно |
| Площадка | `Название площадки` | желательно |
| Преподаватель | `Преподаватель` | желательно |
| Город | `Город` | желательно |
| Статус | `Имя статуса` | желательно |
| Contact ID | `ID контактов` | да для входа через MAX |
| Имена контактов | `Имена контактов` | желательно |

Если у ученика несколько Contact ID, укажите их в одной ячейке через запятую, точку с запятой, перенос строки или `/`.

Пример:

| ID сделки | ID ученика | Имя ребенка из LMS | Фамилия ребенка из LMS | Название группы LMS | Название площадки | Преподаватель | Город | ID контактов | Имена контактов |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1357 | ST-001 | Алиса | Васильева | Python Start, вс 10:00 | Союзный 45 | Олейник Д | Нижний Новгород | 681; 682 | Мама Алисы |

Команда импорта:

```powershell
.\max_bot_venv\Scripts\python.exe -m app.cli.import_crm --path "D:\path\crm.xlsx" --partner-slug partner-a --partner-name "Партнер A"
```

## Формат Google Sheets

Для черновика лучше держать отдельную таблицу с такими листами:

### `orders`

| Колонка | Назначение |
| --- | --- |
| `order_number` | номер заказа, ключ для обновлений |
| `created_at` | дата создания |
| `tenant_slug` | контур города и партнера |
| `max_user_id` | MAX user_id автора |
| `student_id` | внутренний ID ученика |
| `student_name` | имя ученика для проверки |
| `status` | статус заказа |
| `total_astrocoins` | сумма в астронах |
| `items_json` | товары заказа JSON-строкой |
| `venue_name` | площадка |
| `teacher_name` | преподаватель |
| `comment` | комментарий |

### `products`

| Колонка | Назначение |
| --- | --- |
| `tenant_slug` | контур города и партнера |
| `sku` | артикул, ключ товара |
| `name` | название товара |
| `category` | категория |
| `price_astrocoins` | цена |
| `status` | `active`, `hidden` или `archived` |
| `photo_url` | ссылка на фото |
| `description` | описание |

Для прямой загрузки админом в miniapp можно использовать CSV/XLSX с колонками:

```csv
sku,name,category,price_astrocoins,quantity,warehouse,description,photo_url,status
PEN-LOGO,Ручка металл с лого,Канцелярия,120,18,Союзный 45,Сувенирная ручка,,active
```

Обязательные колонки: `sku`, `name`, `category`, `price_astrocoins`, `quantity`, `warehouse`.
Русские заголовки тоже поддерживаются: `артикул`, `название`, `категория`, `цена`, `остаток`, `склад`.

### `inventory`

| Колонка | Назначение |
| --- | --- |
| `tenant_slug` | контур города и партнера |
| `warehouse_slug` | склад |
| `sku` | артикул товара |
| `available_quantity` | доступно |
| `reserved_quantity` | зарезервировано |
| `issued_quantity` | выдано |
| `returned_quantity` | возвращено |

## Подключение Google Sheets

1. Создать проект в Google Cloud.
2. Включить Google Sheets API.
3. Создать service account.
4. Создать JSON-ключ service account и сохранить файл локально, не в git.
5. Открыть нужную Google-таблицу и выдать service account права `Editor` по email из поля `client_email` в JSON.
6. В `.env` указать:

```env
GOOGLE_SERVICE_ACCOUNT_FILE=D:\secure\google-service-account.json
GOOGLE_SHEETS_ORDERS_SPREADSHEET_ID=spreadsheet_id_from_url
```

`spreadsheet_id` берется из URL таблицы:

```text
https://docs.google.com/spreadsheets/d/<spreadsheet_id>/edit
```

После этого backend будет добавлять строки заказов и обновлять статусы через сервисы
`app.services.google_sheets.GoogleSheetsClient` и `app.services.order_sheets`.
Если Google Sheets не настроен, оформление, выдача и отмена заказов продолжают работать без экспорта.

## Настройки для чернового запуска

В `.env.example` добавлены:

```env
MAX_BACKEND_API_BASE=http://127.0.0.1:8000/api/v1
DEFAULT_TENANT_SLUG=nizhniy-novgorod-partner-a
```

Для проверки backend-сценария эти же значения нужно добавить в локальный `.env`.
